## 0. Границы

### В границах (обязано быть реализовано и проверено)

- Запись symlink-inode в ext2 (fast + slow) и hardlink через общий inode — только тем же
  журналируемым путём (`Tx` + WAL), что и остальные мутации (§2, §3, §6).
- `readlink`/`readlinkat`, `lstat` (`newfstatat` + `AT_SYMLINK_NOFOLLOW`), follow-семантика
  `stat`/`fstat`/`open`/`access`/`chdir`/`execve`, политика `ELOOP` (§4).
- Распаковка `data.tar`: реальные ссылки вместо копий, включая GNU longname/longlink и
  ustar `prefix`; удаление `materialize_symlinks` (§5).
- Host-свойства на все чистые части; in-guest проверки (§8, §9).
- Обновление документации: `src/fs/README.md`, `src/pkg/README.md`, корневой `README.md`
  (там прямо написано «materialized as file copies» — `README.md:115,453-454`).

### Вне границ (не требовать от t14–t17)

- Новые syscalls: `symlink(2)`=88, `link(2)`=86, `linkat(2)`=265, `mknod`, `O_PATH`,
  `AT_EMPTY_PATH`, `fchmodat`, `utimensat`. В `abi.rs::supported_set_is_exact`

  (`pkg::install_fs`) создаёт ссылки внутренним API, syscall'ы ему не нужны.
- xattr/ACL (`i_file_acl` всегда 0, `s_feature_*` сняты), symlink-inode в `s_inode_size > 128`.
- Таймстемпы (`i_atime/i_ctime/i_mtime` пишутся нулями — как и сейчас).
- Полноценный `rename(2)` как перенос dirent (см. §4.7 — там только запрет материаллизации).
- pax-формат (`x`/`g`) как обязательный: допустим отказ всего архива (§5.4).
- dpkg/dpkg-deb как установщик; `procfs` (#11) — `/proc/self/exe` только не сломать (§4.9).

| длина цели | `i_size` | `i_blocks` | где цель | mode | links |
|---|---|---|---|---|---|
| 1 … **59** | = длина | **0** | в `i_block` (байты `0..len`, NUL в `i_block[len]` внутри тех же 60 байт) | 0777 | 1 |
| **60**, 61, 200 | = длина | **8** | блок данных, цель с offset 0, **далее NUL**, хвост блока нули | 0777 | 1 |

- путь > 100 → запись `'L'` (`name = ././@LongLink`, `size = len+1`, content = путь + NUL)

- ustar (`--format=ustar`): длинный путь = `prefix` + `/` + `name`.

## 2. (а) Symlink-inode: fast и slow

**REQ-L1 (запись).** Целевая строка `target` (байты как пришли из архива, без NUL):

- `target.len() <= 59` → **fast**: `i_mode = S_IFLNK|0o777`, `i_size = len`,
  `i_links_count = 1`, `i_blocks = 0`, `i_block[0..len] = target`,
  `i_block[len] = 0`; остальные байты `i_block` — 0 (inode пишется из `Ext2Inode::zeroed()`).
  Блока данных нет; ничего в `Tx::data` не попадает.
- `target.len() >= 60` → **slow**: те же mode/size/links, но `i_blocks = 8`
  (`BS/512`), цель пишется с offset 0 выделенного блока данных, хвост блока — нули
  (`Tx::alloc_zeroed_block` уже возвращает нулевой блок), т.е. NUL после цели есть
  аппаратно. Блок обязан идти через `Tx::data_block(blk, true)` — см. §6.2.

**REQ-L2 (чтение).** Fast ⟺ `(i_mode & 0xF000) == S_IFLNK && i_blocks == 0 && i_size <= 60`.
Это ровно linux-проверка `i_blocks - ea_blocks == 0`, где `ea_blocks = 0`, потому что
xattr-фича выключена и `i_file_acl` всегда 0. Чтение fast — `i_block[0..i_size]`;
`i_size == 60` у fast-инода возможен только в чужом образе: отдаём все 60 байт
(Linux в этом случае вернул бы 59 — расхождение допустимо, **наши** образы такого не
создают). Slow — обычный `read_file`-путь на `i_size` байт; отсутствующий первый блок →
`FsError::Corrupt`.

**REQ-L3 (граница).** Порог именно **59/60**, а не «60 байт»: fast хранит цель вместе с
терминирующим NUL в 60 байтах `i_block`. Цель ровно 60 байт обязана стать slow —
иначе Linux потеряет последний символ при чтении (проверено на e2fsprogs, §1.4).

**REQ-L4 (пустая цель).** Ссылка с пустой целью **не создаётся никогда** (§5.5). На чтение
`i_size == 0 && i_blocks == 0` — валидный fast-инод с пустой целью (возвращаем пустую
строку), а не ошибка.

**REQ-L5 (API ext2).** `Ext2Fs::create_symlink(parent_ino: u32, name: &str, target: &str)
-> Result<u32, FsError>` — один `Tx` (§6.2), возвращает номер inode. Правила имени и
дубликатов — как у `create` (`mod.rs:1074-1083`): пустое/`.`/`..` → `Corrupt`,
`> 255` байт → `NameTooLong`, существующее имя → `AlreadyExists`.
`Ext2Fs::read_symlink(ino: u32) -> Result<Vec<u8>, FsError>` возвращает **ровно
`i_size`** байт цели (без NUL), `Corrupt` если inode не симлинк.

**REQ-L6 (защита записи).** `write_file`/`truncate_file` обязаны отвергать любой inode,
у которого `!(i_mode & 0xF000 == S_IFREG)`, а не только каталоги (сейчас `mod.rs:1233,1255,1313`
проверяют `is_dir()`). Без этого запись в symlink-inode интерпретирует байты цели как
номера блоков (`inode::block_for_offset` читает `i_block` как указатели).

**REQ-L7 (dirent).** Структура dirent не меняется: `file_type` остаётся 0
(`dir.rs:45-50`, `s_feature_incompat == 0`), тип выводится из `i_mode`. `insert_dirent`
переиспользуется как есть.

## 3. (б) Hardlink: общий inode + `i_links_count`

**REQ-H1 (создание).** `Ext2Fs::link(parent_ino: u32, name: &str, target_ino: u32)
-> Result<(), FsError>` — один `Tx` (§6.3), который:
1) читает target-inode; `Corrupt`, если он не существует/`i_links_count == 0`;
   отказ, если это каталог: **hardlink на каталог запрещён** (реализовано как
   `AlreadyExists` — так же, как `unlink` сообщает о непустом каталоге; важно, что это
   **не** `Corrupt`/`IoError`, иначе установщик принял бы отказ за «нет места», см. §6.4-I6);
2) `i_links_count += 1` (guard на `u16::MAX` — отказ, значение недостижимо на практике);
3) `insert_dirent(parent_ino, name, target_ino)`.
`i_size`, `i_blocks`, `i_block` цели **не меняются**; блоки данных и inode не аллоцируются;
копирования содержимого нет. Имя-дубликат в каталоге → `AlreadyExists` (проверяется и внутри
транзакции в `insert_dirent`: внешний `lookup_entry` работает вне tx-лока, а двойная вставка
одного имени создала бы два dirent на один inode и сломала учёт ссылок).

**REQ-H2 (удаление).** `unlink(parent, name)`:
- **каталог** (пустой — иначе `AlreadyExists`) освобождается **целиком всегда**: его
  `i_links_count` считает `.`/`..`, а не имена, и хардлинков на каталоги не бывает, поэтому
  ветка «на inode ещё указывают другие имена» к нему неприменима (`rmdir` приходит сюда же
  через `VfsNode::remove`). Применить к каталогу правило счётчика — значит после `rmdir`
  оставить в ФС и inode, и его блок (найдено при реализации t14);
- для **не-каталога** читается `child.i_links_count`:
  - `> 1` → `i_links_count -= 1`, dirent удаляется, **блоки и бит inode-битмапа не трогаются**;
  - `== 1` → существующий путь (`free_all_blocks` + `free_inode_bit`, `mod.rs:1176-1178`),
    плюс `i_links_count = 0`, чтобы host-инструмент не увидел «1 ссылка, dirent нет»;
  - `== 0` → `FsError::Corrupt` (inode уже свободен, dirent битый): «освободить ещё раз»
    означало бы освободить переиспользованный inode.

Всё — в одной транзакции с удалением dirent (§6.3, инвариант I1). Порядок «удалить dirent →
уменьшить счётчик» или наоборот внутри `Tx` не важен (атомарность даёт WAL), важен
**один** коммит.

**REQ-H3 (`st_nlink`).** `st_nlink = i_links_count` для ext2-узлов (и файлов, и каталогов:
у каталога это `2 + число подкаталогов`); дефолт `1` для ramfs/`/dev`. Сегодня жёстко 1
(`io_sys.rs:980`) — заменить.

**REQ-H4 (идентичность).** Два имени одного inode дают равные `st_ino` и одинаковый
`st_dev`. `st_ino == fs_ino() == номер inode` (`mod.rs:1372,1438`, `node_ino` `io_sys.rs:919-924`).
Это и есть определение hardlink — никаких «виртуальных» hardlink'ов через копии.

**REQ-H5 (известное ограничение — не регресс).** Удаление последней ссылки при открытом fd
не защищено (узел живёт в `Arc`, блоки могут быть переиспользованы). Так было и раньше;
обязано быть записано в `src/fs/README.md` как известное ограничение.

**REQ-H6 (нет восстановления).** `i_links_count` никто не чинит: `recover()` реплеит только
закоммиченные транзакции, `reconcile_free_counts` (`mod.rs:853-913`) выправляет **только**
счётчики свободного по битмапам, fsck в системе нет. Ошибка учёта ссылок необратима →
обязательное host-свойство §8.6.

## 4. (в) `readlink`, `lstat`, `stat`/`open`: семантика и `ELOOP`

### 4.1 Что следует за конечной ссылкой, а что нет

| Операция | Follow конечного компонента | Примечание |
|---|---|---|
| `newfstatat` без флагов (`stat`), `fstat` | **да** | висячая цель → `ENOENT` |
| `newfstatat` + `AT_SYMLINK_NOFOLLOW` (**`lstat`**) | **нет** | `S_IFLNK|0777`, `st_size = len(target)` |
| `readlink`/`readlinkat` | **нет** | `EINVAL`, если это не ссылка |
| `open`/`openat` (без `O_NOFOLLOW`) | **да** | открывается цель |
| `open` + `O_NOFOLLOW` | нет | конечный компонент — ссылка → **`ELOOP`** |
| `access` | да | висячая → `ENOENT` |
| `chdir` | да | ссылка на каталог работает |
| `execve` (образ и `PT_INTERP`) | да | `task/process.rs:375-416` |
| `unlink` | **нет** | удаляется сама ссылка (§4.7) |
| `rmdir` | **нет** | на ссылке → `ENOTDIR` |
| `link` (источник) | нет | hardlink на саму ссылку (как `link(2)` без `AT_SYMLINK_FOLLOW`) |
| `rename` | нет | см. §4.7 |
| **промежуточные** компоненты (все операции) | **да**, всегда | общий бюджет переходов §4.6 |

Константы: `AT_SYMLINK_NOFOLLOW = 0x100`, `O_NOFOLLOW = 0o400000`,
`DT_LNK = 10`, `SYMLOOP_MAX = 40`, `Errno::ELOOP = 40`, `Errno::ENAMETOOLONG = 36`.
Добавление вариантов в `Errno` (`errno.rs`) требует проверки исчерпывающих `match` по
`Errno` в ядре; чистый энкодер `encode_errno` (`errno.rs:79-81`) не меняется.

### 4.2 `readlink`/`readlinkat`

- Путь не существует → `ENOENT`; узел существует и не симлинк → `EINVAL`; `bufsiz == 0` → `EINVAL`.
- Возврат: **`min(bufsiz, len(target))`** байт цели, **без** терминирующего NUL;
  `len > bufsiz` — нормальная усечённая запись, не ошибка.
- Буфер пользователя проверяется как сейчас (`check_user_ptr` → `EFAULT`).
- Синтетический случай `/proc/self/exe` **сохраняется** и не должен сломаться
  (его читает libuv `uv_exepath`, а форкнутый ребёнок nvim переисполняет путь).
  рекомендуется выразить его через общий механизм (`readlink() == Some(exe_path)` —
  ровно то, что вводит `docs/procfs.md` §6.1), тогда `readlink`/`lstat`/`stat`
  на нём согласованы; если p1-impl (procfs, #11) уже сделал общий механизм — переиспользовать
  его, а не дублировать.
- `readlinkat`: `dirfd` по-прежнему игнорируется (пути резолвятся от cwd), поведение как у
  `readlink` — кроме случая, когда p1-impl добавит `dirfd`-относительность: тогда не ломать
  `AT_FDCWD`.
- Завершающий `/`: путь трактуется как «конечный компонент обязан быть каталогом»,
  поэтому ссылка в нём разыменовывается; `readlink("link/")` → `EINVAL`
  (или `ENOTDIR`, если цель — не каталог). Достаточно одного из двух, зафиксировать в коде.

### 4.3 `lstat` (`newfstatat` + `AT_SYMLINK_NOFOLLOW`)

- Резолв **без** follow конечного компонента (`lookup_path`; follow-вариант —
  `lookup_path_follow`, §7.4).
- Поля: `st_mode = S_IFLNK | 0o777` (ext2-ссылки всегда 0777),
  `st_size = i_size = len(target)`, `st_nlink = i_links_count` (обычно 1),
  `st_ino = номер inode`, `st_dev = STAT_DEV_VFS`,
  `st_blocks` = `i_blocks` в 512-байтных единицах (fast → 0, slow → 8).
- Остальные флаги `_flags` (например `AT_EMPTY_PATH`) остаются неподдержанными — как сейчас;
  `AT_SYMLINK_NOFOLLOW` — обязателен.
- Прочие биты `_flags`, которые сейчас игнорируются, продолжают игнорироваться (документировать).

### 4.4 `stat`/`fstat`

- `stat` следует; цикл → `ELOOP`; висячая цель → `ENOENT`.
- `fstat` дескриптора, открытого на ссылку, показывает **цель** (иначе и быть не может:
  fd получается только через follow, `O_PATH` вне границ).
- `stat_mode_for` (`io_sys.rs:949-965`) обязан различать `S_IFLNK`; для не-ext2 узлов
  поведение не меняется.

### 4.5 `open`/`openat`

- `O_NOFOLLOW` + конечный компонент-ссылка → **`ELOOP`** (не `EINVAL`).
- `O_CREAT|O_EXCL` при уже существующем имени, **включая висячую ссылку** → `EEXIST`.
- `O_CREAT` без `O_EXCL` по существующей ссылке → открывается/усекается **цель**,
  новый файл не создаётся.
- `O_TRUNC` по ссылке усекает цель.
- Открытие каталога-ссылки даёт каталог-цель (существующее поведение `OpenObject::Dir`).

### 4.6 `ELOOP` и `ENAMETOOLONG`

- Бюджет `SYMLOOP_MAX = 40` переходов **на одну операцию разрешения пути** (сбрасывается
  на каждый syscall). Считаются все переходы — промежуточные и конечный; 41-й → `ELOOP`.
- `readlink` считает промежуточные переходы, конечный не разыменовывает.
- Цикл `a → b → a` даёт `ELOOP` ровно за ≤ 41 переход (терминация обязательна; рекурсия
  «в глубину» без счётчика — запрещена).
- Полная развёрнутая длина пути > `PATH_MAX = 4096` (`io_sys.rs:261`) → `ENAMETOOLONG`;
  если решено не добавлять эту константу — `ELOOP`, и это фиксируется в PR.

### 4.7 Прочие пути (`unlink`, `rmdir`, `rename`, `access`, `chdir`, `execve`)

- **`unlink`** обязан резолвить путь **без** follow: существование и «это каталог?»
  проверяются по самой ссылке, иначе `unlink("link→dir")` вернёт `EISDIR` вместо удаления
  ссылки. При выбранной схеме §7.4 (`lookup_path` **не** следует, follow — отдельный
  `lookup_path_follow`) `sys_unlink` (`io_sys.rs:1633-1635`) менять не нужно — требование
  обратное: **не** переводить `unlink`/`rmdir`/`rename`/`chmod` на `lookup_path_follow`.
  Если же исполнитель выберет follow-по-умолчанию, эти пять вызовов обязаны перейти на
  no-follow резолвер — иначе удаление ссылки в каталог перестанет работать.
- **`rmdir`** — no-follow; ссылка → `ENOTDIR`.
- **`rename`** — существующая реализация (`rename_paths`) читает источник целиком и пишет
  новый **обычный** файл. Для источника-ссылки это материализация (мусор вместо ссылки).
  Минимально допустимо: отказ (`EINVAL`/`ENOSYS`) без изменения дерева; рекомендуется:
  перенос dirent в одной транзакции (`unlink`+`insert_dirent` в одном `Tx`), при котором
  inode не меняется. **Материализация ссылки запрещена.**
- **`access`**, **`chdir`** — follow (правка не нужна, кроме §7.4).
- **`execve`/`PT_INTERP`**: литеральный путь `/mnt/lib64/ld-linux-x86-64.so.2` после t15
  резолвится через реальную ссылку; merged-usr фоллбэк (`process.rs:397-413`) оставить как
  страховку, но он больше не должен быть единственным путём. Рекомендуется записывать в
  `cs.exe_path` уже разрешённый путь (Linux-canonical), чтобы `/proc/self/exe` не показывал
  ссылку.

### 4.8 `getdents64`

- `d_type` для ссылки — `DT_LNK (10)`: `dir → DT_DIR`, `readlink().is_some() → DT_LNK`,
  иначе `DT_REG` (та же формула, что в `docs/procfs.md` §5.3) — `dirent.rs` + `io_sys.rs:1726`;
  каталог/файл как сейчас.
- `d_ino` — **реальный номер inode** (`node_ino(&child)`), а не `index + 1`
  (`io_sys.rs:1727`): иначе `ls -i`/`find` видят у двух хардлинков разные «файлы», хотя
  `stat` даёт одинаковый `st_ino` — внутреннее противоречие, которое ловит t17.
  Существующих проверок на синтетическое значение нет (`selftest_lx::check_getdents`
  проверяет только наличие записей), `d_off` не меняется.

### 4.9 `/proc/self/exe`

Не ломать (§4.2). Если t3/procfs уже отдаёт узел — выразить его как синтетическую ссылку.

## 5. (г) Что делает tar-распаковка

### 5.1 Разделить `TarType`

`TarType::{Regular, Directory, Symlink, Hardlink, Other}`:
`'0'/NUL → Regular`, `'5' → Directory`, **`'2' → Symlink`**, **`'1' → Hardlink`**,
остальное (включая `'L'`, `'K'`, `'x'`, `'g'`, `'3'`, `'4'`, `'6'`) → `Other`.
`link_target` заполняется для **обоих** видов ссылок.
Обновить потребителей: `src/pkg/install.rs:117` (+ доккомментарии `102-111`),
`src/pkg/install_fs.rs:68,102`, `host-tests/.../p24.rs:71`, `p26.rs:19-21,92`.
`Install`-модель (`install_model`) может остаться «только Regular», но тогда рядом должен
появиться чистый планировщик ссылок (§8.9).

### 5.2 GNU longname `'L'` / longlink `'K'` — обязательны

- `'L'`: content записи (ровно `size` байт) — **путь следующей** записи; `'K'`: content —
  **`linkname` следующей** записи. Хвостовые NUL обрезать.
- Сами `'L'`/`'K'` записями не являются и не должны попадать в `Vec<TarEntry>`.
- Порядок `K` → `L` → запись (GNU tar) и обратный — поддержать оба; две `'L'` подряд —
  побеждает последняя.
- `'L'`/`'K'` в конце потока — молча отбросить (не создавать файл с именем `@LongLink`).
- Не-UTF-8 длинное имя/цель → `TarError::LengthInconsistent` (как сейчас для поля `name`,
  `tar.rs:213`).
- Zero-copy и `Copy` у `TarEntry` желательно сохранить: content `'L'`-записи — срез того же
  буфера, поэтому `&'a str` из него корректен.

**Это исправление существующего бага:** сейчас `'L'` пропускается, а следующая запись
устанавливается по **обрезанному** имени (молчаливая порча дерева) — прямо запрещено §5.4.

### 5.3 ustar `prefix`

Если `prefix` (байты `345..500`) непуст, действующий путь — `prefix + "/" + name`
(проверено на `--format=ustar`). `OFF_PREFIX` уже объявлен (`tar.rs:35`), но не используется.
Требуемый результат: установщик использует склеенный путь. Форма — на выбор исполнителя
(поле `prefix: &'a str` в `TarEntry` + чистый хелпер склейки, либо owned-строка); важно, что
`prefix` доводится до `install_fs`.

### 5.4 Непонятые расширения — не «молча»

Любой контейнер расширений, который парсер не понял (`'x'`, `'g'`, неизвестный typeflag с
непустым content), обязан либо быть обработан, либо привести к отказу **всего** архива
(новый вариант `TarError`). Установка файла по обрезанному/угаданному пути запрещена.
Минимум для `'x'`/`'g'`: читать `path=`/`linkpath=` (простой текстовый формат) — тогда
поддержка pax появляется «бесплатно» и покрывается host-свойством.

### 5.5 Пустая цель

Symlink/hardlink с пустым `link_target` **не создаётся**: один `crate::warn!` с
`component=Package_Installer` и пропуск (как сейчас `install_fs.rs:143-150`).

### 5.6 Порядок, цели, замена

- **Symlink** создаётся сразу, в порядке архива. Висячая цель — **норма** (`ln -s` не
  проверяет существование): никаких проверок цели, никаких повторов.
- **Hardlink** требует уже существующей цели. Основной проход + отложенная очередь,
  повторяемая до отсутствия прогресса (цепочки `a→b→c`; каждый проход обязан создавать ≥ 1
  ссылку, иначе выход). Неразрешённые — по одному `warn` на ссылку, пропуск.
  **Никогда не копия.**
- Цель **hardlink** — архивный путь: нормализуется `normalize_entry_path` (снимает `./`,
  `/`, разрешает `..`), как сейчас (`install_fs.rs:137-141`).
- Цель **symlink** — **дословная** строка из архива: не нормализуется, не резолвится
  относительно install-root, не проверяется. Именно это возвращает работу `$0`-относительным
  скриптам и `alternatives`-алиасам. Нынешняя нормализация абсолютных целей
  (`install_fs.rs:110-114`) удаляется.
- **Резолв цели hardlink — без follow** (lstat-семантика): если цель — ссылка, hardlink
  вешается на её inode; если каталог — пропуск + `warn`; если отсутствует — в очередь.
- **Замена существующего**: если по пути ссылки что-то есть — существующая запись удаляется
  (с link-aware `unlink`, §3), затем создаётся ссылка. Если существующее — каталог: пропуск
  + `warn` (никакого рекурсивного удаления). Дубликаты пути в одном архиве: побеждает
  последняя запись (last-writer-wins, как у файлов `install.rs:107`).
- **Родительские каталоги** создаются неявно, как сейчас, но резолвятся **с follow**:
  если `/lib64` — существующая ссылка на `usr/lib64`, установка `lib64/foo` обязана попасть
  в `usr/lib64/foo`, а не создать дубликат дерева (§7.4).
- Каталоги архива по-прежнему создаются только как родители, их mode игнорируется — поведение
  не меняется (зафиксировать в README).
- Счётчик `installed` в `install_data_tar` увеличивается и на symlink, и на hardlink
  (по 1 за созданную запись); пропущенные не считаются.

### 5.7 Что удалить

`materialize_symlinks` (`install_fs.rs:97-191`) удаляется целиком; `read_regular_file`
(`install_fs.rs:195-213`) — если больше не нужен. Обновить: `src/pkg/README.md:68-69`,
`README.md:115,453-454`, `src/pkg/install_fs.rs` (доккомментарий `12-30`).

### 5.8 Чистый writer

`write_tar` (`tar.rs:294-339`) умеет только REG. Расширить (или добавить `write_tar_full`)
для symlink/hardlink/longname/prefix — это нужно in-guest селфтесту (§9.1), т.к. он строит
`data.tar` в ядре через `write_tar`.

## 6. (д) Журнал/WAL: какие транзакции нужны

### 6.1 Механика (как есть, менять не нужно)

`Tx` копит грязные блоки и на `commit()` (`mod.rs:534-579`): (1) вписывает `sb` + GD в их
блоки, (2) **пишет файловые данные напрямую в финальные места ДО метадата-транзакции**
(ordered mode, `mod.rs:551-560` — коммитнутые метаданные никогда не указывают на
незаписанные данные), (3) отдаёт **остальные** (метаданные) блоки в WAL **одной** атомарной
транзакцией, (4) публикует `sb`/`gds` в памяти. Лимит: `count + 3 <= log_blocks = 64`
(`journal.rs:213-215`) → не более **61** грязного блока на транзакцию; `> 254` → `OutOfSpace`.

### 6.2 `create_symlink` — ровно один `Tx`

Грязные блоки: inode-битмап, sb, GD, блок inode-таблицы (mode/size/links + `i_block`),
блок(и) родительского каталога (при нехватке места — +1 новый блок через `map_or_alloc`),
для slow — блок данных. Итого `≤ 7` грязных блоков при fast и `≤ 8` при slow; **в WAL едут
только метаданные**, поэтому лимит `≤ 61` (`count + 3 ≤ 64`) не зависит от длины ссылки:
`≤ 7` в обоих случаях.

**Обязательно для slow:** целевой блок данных обязан быть помечен как data
(`Tx::data_block(blk, true)`), т.е. физически записан до коммита метаданных. Если записать
его как обычный metadata-блок через `Tx::block`, атомарность сохранится (блок поедет в WAL),
но: (а) сломается ordered-инвариант «данные на месте раньше метаданных», (б) на каждую
ссылку будет тратиться 1 из 64 слотов WAL. Требование контракта — `data_block`.

**Fast:** блоков данных нет, всё — метаданные (в `Tx::data` пусто).

### 6.3 `link` / `unlink` — по одному `Tx`

`link`: блок inode-таблицы цели (`i_links_count`) + блок родительского каталога (+возможный
новый блок каталога) → 2–4 блока. Блоков данных нет.

`unlink`: блок dirent + (при `links_count == 1`) битмап блоков, блоки indirect, inode-битмап,
sb, GD. Удаление dirent и `free_inode_bit` **обязаны быть в одной транзакции** — иначе крах
между ними оставит dirent, ссылающийся на свободный inode (инвариант I1). Сейчас это уже так;
при добавлении ветки `links_count > 1` — сохранить.

### 6.4 Инварианты (проверяемые, не «пожелания»)

- **I1** dirent ⇒ inode не свободен (бит в inode-битмапе установлен).
- **I2** `i_links_count > 0` ⇒ существует ≥ 1 dirent на этот inode.
- **I3** `i_links_count` == числу dirent'ов (для каталога: `2 +` подкаталоги).
- **I4** `S_IFLNK && i_blocks == 0` ⟺ fast (цель в `i_block`); slow ⇒ блок данных записан
  до того, как ссылка станет видимой (committed).
- **I5** блоки/inode освобождаются **только** при `i_links_count == 1`; иначе живое имя
  потеряет данные.
- **I6** ни одна операция не превышает 61 грязного блока (иначе `OutOfSpace` → ложный
  `NoSpace` в установщике: `VfsError::IoError` → `InstallError::NoSpace`, `install_fs.rs:26-30`).
- **I7 (найдено при реализации t14)** *освобождение* блоков тоже обязано быть mode-aware:
  `free_all_blocks` обходит `i_block` как карту блоков, а у **fast**-ссылки там лежит текст
  цели — обход освободил бы блоки, номера которых складываются из байтов цели (произвольные
  освобождения). Fast-ссылка не владеет ни одним блоком, slow-ссылка — ровно одним
  (`i_block[0]`), и только REG/DIR идут обычной картой (`mod.rs::Tx::free_inode_blocks`).

### 6.5 Чего журнал НЕ делает

`recover()` реплеит только закоммиченные транзакции и идемпотентен; `reconcile_free_counts`
(`mod.rs:853-913`) чинит **только** счётчики свободного по битмапам; `i_links_count` и
типы dirent не восстанавливаются; fsck нет. Отсюда: I1–I3 держатся исключительно писателем.

### 6.6 Почему ordered-порядок безопасен

Крах после прямой записи блоков данных, но до коммита WAL: on-disk битмап ещё помечает эти
блоки свободными, ссылка не видна — мусор лежит в свободных блоках и будет перезаписан.
Видимых нарушений нет. (Симметрично: крах до записи данных не оставит коммитнутых
метаданных, указывающих на них.)

## 7. Минимальная поверхность API

### 7.1 `VfsNode` — поверхность согласована с `docs/procfs.md` (t3, issue #11)

Источник истины «узел — ссылка» — **один** метод `readlink()` (его же вводит срез procfs
для `/proc/self/exe`); отдельный предикат `is_symlink()` не заводить, чтобы не было двух
расходящихся источников правды.

```rust
/// Цель символической ссылки, если узел — ссылка (по умолчанию `None`).
fn readlink(&self) -> Option<String> { None }        // вводится docs/procfs.md §6.1
/// Число жёстких ссылок (ext2: i_links_count; по умолчанию 1).
fn nlink(&self) -> u64 { 1 }                          // вводится #18
fn create_symlink(&self, name: &str, target: &str) -> VfsResult<Arc<dyn VfsNode>> {
    Err(VfsError::NotSupported)
}
fn link(&self, name: &str, target: &Arc<dyn VfsNode>) -> VfsResult<Arc<dyn VfsNode>> {
    Err(VfsError::NotSupported)
}
```

- `readlink()` == `None` ⟺ узел не ссылка; для ext2-ссылки он обязан быть `Some(цель)`,
  иначе `lstat`/`getdents`/`readlink` разъедутся.
- `link` берёт номер inode источника из `target.fs_ino()` (0 → `InvalidArgument`).
- **Обязательно** форвардить `readlink()` и `nlink()` в `MountNode` (`vfs/mod.rs:202-242`):
  `ext2` смонтирован в `/mnt`, и `stat("/mnt")` обязан показывать `i_links_count` корневого
  каталога, как Linux. В срезе procfs форвардинг не нужен (там `MountNode` ни при чём:
  конечный узел возвращается самим `lookup`), но в #18 он обязателен — это требование
  **сверх** `docs/procfs.md` §6.4 (там прямо написано «требований на изменение `MountNode`
  в этом срезе нет»). Остальные реализации (`NullDevice`, `SerialDevice`, `DevDirectory`,
  `RootDirectory`, `RamDir`, `RamFile`) живут на дефолтах.
- `VfsNode::lookup` остаётся **одношаговым и без follow**: `Ext2Dir::lookup("link")` возвращает
  узел-ссылку. Политика follow живёт в резолвере, а не в `lookup`.

### 7.2 Узлы ext2

- `Ext2Symlink { fs, ino, name, cached_size }`: `size() = i_size` (длина цели),
  `readlink() = Some(цель)`, `fs_ino() = ino`, `nlink() = i_links_count`,
  `read/write/truncate = NotSupported`.
- `node_for` (`mod.rs:960-978`) диспетчеризует **явно**: `S_IFDIR → Ext2Dir`,
  `S_IFLNK → Ext2Symlink`, `S_IFREG → Ext2File`; всё прочее — узел с `NotSupported`
  на read/write (чужой образ с device-node не должен читаться как файл).
- `nlink()` у `Ext2Dir`/`Ext2File`/`Ext2Symlink` — из `i_links_count` (с `cached_size`-подобным
  фоллбэком 1 при ошибке чтения inode).

### 7.3 Новые операции ext2

```
Ext2Fs::create_symlink(parent_ino: u32, name: &str, target: &str) -> Result<u32, FsError>
Ext2Fs::link(parent_ino: u32, name: &str, target_ino: u32) -> Result<(), FsError>
Ext2Fs::read_symlink(ino: u32) -> Result<Vec<u8>, FsError>
```
Все — через `Tx` (§6); `unlink` становится link-aware (§3, REQ-H2); `write_file`/`truncate_file`
отвергают не-REG (REQ-L6).

### 7.4 Резолверы VFS

**Семантику `lookup_path` не меняем** (решение `docs/procfs.md` §5.4): она остаётся
одношаговой-без-follow, и на ней остаются все no-follow потребители (`readlink`, `lstat`,
`unlink`, `rmdir`, `rename`, `chmod`). Добавляется отдельная точка входа:

```rust
// src/vfs/mod.rs — новый, отдельно от lookup_path (её семантика не меняется)
pub fn lookup_path_follow(path: &str) -> VfsResult<Arc<dyn VfsNode>>  // бюджет 40, ELOOP
```

**Матрица вызывающих (обязательна к исполнению):**

| Вызывающий | Резолвер |
|---|---|
| `open_path`/`open_resolved`, `sys_newfstatat` без `AT_SYMLINK_NOFOLLOW`, `sys_access`, `sys_chdir`, `sys_statfs`, `execve`/`PT_INTERP` (`task/process.rs::read_file_all`) | `lookup_path_follow` |
| `sys_newfstatat` + `AT_SYMLINK_NOFOLLOW`, `sys_readlink`, `sys_unlink`, `sys_rmdir`, `rename`, `chmod`, источник `link` | `lookup_path` |
| `install_fs`: корень пакета и **промежуточные** компоненты пути (создание недостающих каталогов, установка под `lib64 → usr/lib64`) | `lookup_path_follow` (или follow-резолв от узла) |
| `install_fs`: **конечный** компонент при замене существующей записи, и цель hardlink | без follow (удаляется сама ссылка, hardlink вешается на неё) |

Дополнительно к `docs/procfs.md` (там бюджет 8 и `ENOENT` + `warn`, DEVIATION-13) #18
требует: бюджет **40** (`SYMLOOP_MAX`, §4.6) и `ELOOP`; `..` после перехода по ссылке идёт
от цели; относительная цель резолвится **от каталога ссылки**, а не от cwd — формула
`resolve_path(target)` из `docs/procfs.md` §5.4 верна только для абсолютных целей, и это
единственное расхождение двух контрактов. Если срез procfs уже влит, t15 **дорабатывает**
`lookup_path_follow`, а не заводит второй помощник.

Резолв относительно узла (для `install_fs` и для целей ссылок):
`resolve_under(root: &Arc<dyn VfsNode>, path: &str, follow_final: bool) -> VfsResult<...>`
с тем же бюджетом.

**Чистый** (host-testable) движок обхода в отдельном модуле (`core`+`alloc`, без `VfsNode`,
`Arc`, `Spinlock`), поверх абстрактного trait'а вида
`lookup(dir, name)`, `kind(node) -> Dir|Symlink|Other`, `link_target(node)`,
`root()`; константа `SYMLOOP_MAX`. Рекомендуемое имя — `src/vfs/link_walk.rs`
(+ `#[path]`-include в `host-tests/src/lib.rs`). Ядро получает тонкий адаптер над
`dyn VfsNode`. Без чистого модуля требования §8.7 нечем доказать.

### 7.5 Абсолютные цели и гостевое пространство имён

ext2 смонтирован в `/mnt`, а гость видит его как `/`. Поэтому абсолютная цель ссылки обязана
резолвиться через **ту же** функцию отображения, что и входной путь syscall'а
(`io_sys.rs:686-733`): `/x` → `/mnt/x`, кроме `dev/tmp/proc/sys`. Требования:

1. отображение — **та же чистая** функция, которую вводит `docs/procfs.md` §1.3/§6.4
   (`guest_path_keeps_root` в `src/arch/x86_64/linux/io.rs`, host-свойство P55); #18 только
   переиспользует её, второй копии не заводить;
2. относительная цель резолвится от каталога, содержащего ссылку, **в кернел-пространстве
   имён** — это эквивалентно гостевому, т.к. `/mnt` — прямой child синтетического корня, и
   `..`, выходящий за пределы ext2-дерева, попадает в тот же узел, что и гостевое `/`;
3. `..` после перехода по ссылке идёт от **цели**, а не от исходного каталога
   (`/mnt/a/b/..`, где `b` → `/mnt/c`, даёт `/mnt/`, а не `/mnt/a/`).

### 7.6 Расхождения и согласования с `docs/procfs.md` (t3, issue #11)

Два контракта пересекаются ровно в трёх точках; здесь зафиксировано, кто что делает, чтобы
t15 не завёл дублирующий механизм:

| Точка | `docs/procfs.md` (t3, срез #11) | #18 (этот контракт) | Итог |
|---|---|---|---|
| `VfsNode::readlink() -> Option<String>` (дефолт `None`) | вводится для `/proc/self/exe` | то же имя и сигнатура: **единственный** источник правды «это ссылка»; отдельный `is_symlink()` не заводится | принимается как есть; ext2 переопределяет `readlink()` для `S_IFLNK` |
| `lookup_path_follow(path)` (новый, рядом с неизменённым `lookup_path`) | бюджет 8, исчерпание → `ENOENT` + `warn` (DEVIATION-13) | бюджет **40** (`SYMLOOP_MAX`) → `ELOOP`; `..` после ссылки — от цели; относительная цель — от каталога ссылки (формула `resolve_path(target)` из §5.4 procfs верна **только** для абсолютных) | один помощник; t15 дорабатывает существующий, `ELOOP`/`ENAMETOOLONG` добавляются в `errno.rs` |
| `MountNode` не форвардит новые методы | «требований на изменение нет» | **обязательно** форвардить `readlink()` и `nlink()`: `stat("/mnt")` обязан показывать `i_links_count` корня ext2 | t15 добавляет 2 форварда в `vfs/mod.rs:202-242`; procfs не затрагивается |

Совпадающие правки делать **один раз** (кто первый влил — тот и сделал):
`DT_LNK` в `dirent.rs`, `d_ino = node_ino(child)`, `AT_SYMLINK_NOFOLLOW` в `sys_newfstatat`,
`sys_readlink` через `lookup_path` + `readlink()`, `guest_path_keeps_root`
(`src/arch/x86_64/linux/io.rs`).

## 8. Host-свойства (чистые части — обязательны)

Все — в `host-tests/src/properties/` (новый файл, например `p51.rs`), модули подключаются
`#[path]` в `host-tests/src/lib.rs`. Каждое свойство — на инвариант, не на пример.

1. **Классификация typeflag:** `'1'`→`Hardlink`, `'2'`→`Symlink`, у обоих непустой
   `link_target`; `'0'`/NUL→`Regular`, `'5'`→`Directory`; прочее→`Other`.
2. **`'L'`:** путь следующей записи == content (без хвостовых NUL); `'L'` не порождает
   `TarEntry`; `'L'` в конце потока не порождает записи; **`'K'`** то же для `link_target`;
   порядок `K,L` и `L,K` равнозначен.
3. **ustar `prefix`:** при непустом `prefix` действующий путь == `prefix + "/" + name`,
   при пустом — `name`.
4. **Границы полей:** symlink с целью ровно 100 байт (без NUL) парсится и **не обрезается**;
   > 100 без `'K'` не превращается в молчаливое усечение в установщике (§5.4/§5.5);
   round-trip `read_tar(write_tar_full(members))` сохраняет `kind`/`path`/`link_target`/
   `content` для REG/SYMLINK/HARDLINK/LONGNAME.
5. **Планировщик fast/slow** (чистая функция от `len`): `≤ 59 → Fast`, `≥ 60 → Slow`
   (границы 0/1/58/59/60/61/large); fast-образ: байты цели + NUL, всего ≤ 60; чтение fast
   обратно даёт ровно цель; `len == 0` → отказ на создание.
6. **Учёт ссылок** (чистая модель inode/dirent-операций): после любой последовательности
   `link`/`unlink` выполняется I3 (`nlink == число имён`); `unlink` при `nlink == 1` →
   освобождение, при `> 1` → только декремент; `nlink == 0` → `Corrupt`; инвариант I5.
7. **Обход ссылок** (чистый движок, §7.4): цикл `a↔b` и самоссылка → `TooManyLinks` за
   ≤ 41 переход (терминация); относительная цель резолвится от каталога ссылки, включая `..`;
   `..` после перехода по ссылке — от цели; абсолютная цель — от корня; промежуточная
   ссылка на каталог следуется; бюджет 40 на операцию и сброс между операциями; висячая
   цель: `lstat`/`readlink` успешны, `stat`/`open` → `NotFound`.
8. **stat-кодек:** расширенный `encode_stat` переносит `st_size/st_mode/st_ino/st_nlink`
   (для ссылки `S_IFLNK|0777`); старый `encode_stat` сохраняет поведение — существующие
   P8/P9 остаются зелёными.
9. **План установки** (чистый): для набора записей планировщик выдаёт операции так, что
   каждая hardlink-операция идёт после создания её цели (или помечена как unresolved);
   symlink-операции сохраняют архивный порядок; последний дубликат пути побеждает;
   `..`-escaping пути отброшены.
10. **dirent:** `d_type` из типа узла (`DT_LNK`=10/`DT_DIR`=4/`DT_REG`=8) — расширение P32;
    `d_ino` == переданному значению.

`abi.rs::supported_set_is_exact` **не меняется** (новых syscalls нет). `host-tests` должен
остаться `core`+`alloc`-совместимым: чистые модули не тянут `VfsNode`/`Spinlock`.

## 12. Риски и грабли (приоритет сверху вниз)

1. **`node_for` → `Ext2File` для симлинка** (`mod.rs:960-978`): `Ext2File::read` вызывает
   `read_file` → `block_for_offset` читает **ASCII-цель fast-ссылки как номера блоков**.
   Это чтение произвольного блока диска. Закрыто в t14 (`Ext2Symlink` + явная диспетчеризация
   по `i_mode`); тот же дефект на пути **удаления** (`free_all_blocks`) закрыт `Tx::free_inode_blocks`
   — см. I7, проверяется in-QEMU тестом («unlinking a fast link frees no block»).
2. **`lookup_path` с follow-по-умолчанию**: если исполнитель сделает follow внутри
   `lookup_path` (вместо отдельного `lookup_path_follow`), `unlink("link→dir")` вернёт
   `EISDIR` и не удалит ссылку, а `readlink` перестанет читать саму ссылку. Матрица §7.4
   обязательна при любом варианте.
3. **`rename` копированием**: симлинк молча становится обычным файлом с мусорным содержимым.
4. **`'L'` без поддержки**: пути > 100 байт ставятся по обрезанному имени (уже сейчас,
   §1.4) — молчаливая порча дерева.
5. **Ссылка в промежуточном компоненте** (`lib64` → `usr/lib64`): без follow в
   `install_fs`/резолвере создаётся дубликат дерева вместо установки внутрь цели.
6. **WAL**: > 61 грязных блоков на операцию → `OutOfSpace` → ложный `NoSpace`
   (`install_fs.rs:26-30`); slow-ссылка, записанная как metadata-блок, — потеря
   ordered-инварианта и слота WAL.
7. **`i_links_count` нечем восстановить** (§6.5) → обязательное свойство §8.6.
8. **Совместимость с e2fsck**: `s_feature_incompat == 0` (нет `filetype`) — тип dirent не
   проверяется, `file_type = 0` оставляем; таймстемпы нулевые (как и раньше).
9. **`/proc/self/exe`**: его читает libuv (`uv_exepath`) → nvim; синтетический случай
   сохранить и покрыть регресс-проверкой (§9.1).
10. **Порог 59/60**: «60 байт» — распространённая ошибка; fast вмещает цель **вместе с NUL**,
    т.е. ≤ 59 символов. Цель ровно 60 байт → slow (проверено на e2fsprogs).
11. **Счётчик `installed`**: hardlink/symlink обязаны считаться, иначе `selftest_lx`/e2e
    зафиксируют «установлено N файлов» не то, что ожидалось.
12. **Абсолютная цель не должна терять оставшиеся компоненты**: `/a/link/..` — это каталог
    ЦЕЛИ минус один уровень (`link → /b/c` даёт `/b`). Резолвер, который при абсолютной цели
    очищает список компонентов, возвращает `/b/c`; поймано host-свойством против независимого
    оракула (`host-tests/src/properties/link_walk_paths.rs`).
13. **Двойной учёт в `install_one`**: удаление существующего пути перед созданием ссылки
    обязано проходить через link-aware `unlink` (§3), иначе удаление одного имени из N
    освободит inode целиком и «обнулит» остальные имена.
