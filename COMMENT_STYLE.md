# COMMENT_STYLE.md — правила волны «русские доки»

Это служебный документ волны перевода/чистки документации. Он не описывает ядро и не
заменяет `AGENTS.md`: здесь только правила, по которым правятся человекочитаемые доки, чтобы
волна оставалась консистентной и не ломала машинно-проверяемые утверждения.

## Область

- В этой волне — корневые доки (`README.md`, `AGENTS.md`, `CHANGELOG.md`, `SECURITY.md`,
  `BRANCHING.md`, `RELEASING.md`), `docs/**` и этот файл.
- `src/**` и README подсистем правят другие агенты; их стиль может отличаться, но правила
  ниже — общий ориентир.
- Код, команды, пути, флаги, имена типов/функций/переменных, вывод логов и содержимое
  code fences **не переводятся и не переписываются**.

## Что сохраняется дословно

1. **Ссылки-идентификаторы:** `R1`…`R11` (R-номера требований), `P1`…`P56` (host-свойства),
   `§N`/`§N.M` (разделы контрактов), `REQ-H*`/`REQ-L*`, `DEVIATION-N`, `issue #N`, номера
   PR, имена selftest-рутин, e2e-режимов, property-файлов и тестов (`p51_*`, `cow_ownership`,
   `install_symlink_confinement`, `LXSELFTEST …`).
2. **Версии, теги и claim'ы:** строки вида `main reads …`, `dev currently reads …`,
   `tags A → B → …`, версии в `Cargo.toml`/`CHANGELOG`/release notes — дословно. Формат
   таблиц, списков и заголовков сохраняется; меняется только язык прозы.
3. **Числа, хэши, размеры и имена артефактов:** `sha256`, `Content-Length`, `ELF`-хэши,
   `LXSELFTEST SUMMARY`, имена файлов (`pagh-vX.Y.Z.elf`, `Packages.gz`, `disk.img`) — как
   есть.
4. **Машинные блоки `AGENTS.md`:** заголовок `## Commands (all six must be green before you
   push)` и его fenced-блок, `## Canonical entry points` и его таблица-декларация,
   инвариант 10 (`**Unsafe policy**`, список путей, `needs a …`), фразы-якоря
   `each folder documents itself`, `never re-save vendored files`, `One deliberate local
   patch`, `excluded from the kernel workspace`, `staticlib`. Их правка — не стиль, а поломка
   гейта `tools/check_agents_md.py`.

## Что удаляется

- **Task/round/field/photo-нарратив:** `задача tNN`, `kind=work`, `ветка …` как история
  работы, имена worktree (`/home/oleg/tNN-*`), «полевой отчёт», «field photo», «фото»,
  «капитан», «верификатор», «независимая верификация», «прогон tNN», «сессия», «агент
  сделал». Остаются факты, команды и evidence — без хроники того, кто и в каком раунде это
  делал.
- **«WHY THIS EXISTS» / «старый драйвер» / «old driver»** и подобные оправдания: если
  объяснение нужно, оно формулируется как инвариант или ограничение, а не как история
  болезни.
- **Длинные истории** сжимаются: оставляем причину, инвариант, точку принуждения и
  доказательство (тест/PoC/гейт); убираем пошаговую реконструкцию отладки.
- **Audit-ID (`F-…`, `F-r…`, `F-LEAD…`, `F-x86…`)** не размазываются по докам: единственная
  статусная страница — `SECURITY.md`. В `README`/`AGENTS`/`CHANGELOG`/`docs/**` находка
  называется описательно («fork-COW ownership UAF», «обход confinement установщика»), а за
  деталями — ссылка на `SECURITY.md`. В самом `SECURITY.md` ID сохраняются: это его
  первичный ключ.

## Как писать прозу

- Язык — русский; технические имена, API и идентификаторы — в `backticks` без перевода.
- Термин можно оставить английским, если это имя интерфейса/протокола (`mmap`, `io_uring`,
  `WAL`, `boot protocol`, `fail-closed`); в остальном — обычный русский технический текст.
- Заголовки можно переводить, но структура (уровни, порядок, якоря внутренних ссылок)
  сохраняется. Если заголовок служит якорем для ссылки, ссылка обновляется вместе с ним.
- Таблицы: формат (число колонок, пайпы, выравнивание) не меняется; переводится текст ячеек.
- Списки: маркеры и вложенность сохраняются; переводится текст пунктов.
- Не добавлять новых обещаний, которых нет в коде/тестах. Если факт неизвестен — писать
  «не проверено» или «задокументированный пробел», а не догадку.
- Сокращая, не терять ограничения и честные оговорки: «не CSPRNG», «только QEMU», «реального
  железа не было», «проверено host-свойствами, не end-to-end» — это часть контракта.

## Проверки перед коммитом

1. `python3 tools/check_agents_md.py` — обязательно зелёный; при правках `AGENTS.md`
   дополнительно `--probe` (гейт должен ловить каждый класс поломок).
2. `python3 tools/check_safety.py` — зелёный (доки не должны описывать другой `unsafe`-политики,
   чем enforced).
3. `git diff --check` — без trailing whitespace и конфликтных маркеров.
4. `git status` — в диффе только доки из области волны; `src/**` не тронут.
5. Ссылки, которые проверяет гейт (`tools/e2e_*.ps1`, `docs/procfs.md`, `host-tests/`, …),
   должны остаться существующими путями.

## Пример

Было (нарратив):

> Задача t25, прогон верификатора 2026-09-17: после долгой отладки капитан исправил гейт
> масштаба, и теперь однострочный контроль не проходит.

Стало (инвариант):

> Гейт масштаба: `bigindex` отказывает индексу ниже `BIGINDEX_MIN_STANZAS = 50_000`
> (`exit 2`; обход для осознанных sub-scale контролей — `--allow-small-index`).
> Доказательство — negative control в §Воспроизведение.
