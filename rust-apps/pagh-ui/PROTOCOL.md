# PGUI v1 — протокол клиента Pagh desktop B

Клиентская часть протокола для userspace-композитора `pagh-desktop`. Документ
описывает ABI, который реализует `pagh-ui` (типы и кодирование —
[`src/protocol.rs`](src/protocol.rs), транспорт — [`src/client.rs`](src/client.rs)).
Серверная сторона (композитор) должна реализовать ровно этот обмен; при
расхождении приоритет у этого файла.

## Транспорт

- `AF_UNIX`, `SOCK_STREAM`. Клиент подключается к сокету композитора
  (путь передаётся приложению аргументом или через окружение).
- Поверх сокета идут кадры:

  ```
  +----------------+-------------------------------+
  | u32 длина (LE) | полезная нагрузка, длина байт |
  +----------------+-------------------------------+
  ```

  Полезная нагрузка начинается с `u8` — кода типа сообщения. `длина` считает
  тип и тело, но не сам префикс. Максимальный кадр, который клиент готов
  принять, — 16 МиБ (`MAX_FRAME`); сервер может ограничить его меньше в
  `welcome`.
- Порядок байт — little endian (x86_64 и riscv64 в Pagh).
- Строки — `u16` длина + UTF-8 байты (без завершающего нуля).
- Буферы пикселей — `u32` длина + данные.

После подключения клиент сразу шлёт `hello`, сервер отвечает `welcome`. До
`welcome` других кадров быть не должно; клиент ждёт ответ не дольше 5 секунд.

## Форматы пикселей

| Код | Имя        | Байт/пиксель | Упаковка                 |
|-----|------------|--------------|--------------------------|
| 1   | XRGB8888   | 4            | `0x00RRGGBB`             |
| 2   | ARGB8888   | 4            | `0xAARRGGBB`             |
| 3   | RGB565     | 2            | `RRRRRGGGGGGBBBBB`       |

Строка поверхности — `stride` байт; для полного кадра `stride = ширина ×
байт/пиксель`. Композитор сообщает предпочтительный формат в `welcome`, клиент
шлёт кадры в нём.

## Сообщения клиента

### 1 — `hello`

| Поле           | Тип      | Значение                                  |
|----------------|----------|-------------------------------------------|
| `magic`        | `u32`    | `0x50475549` (ASCII «PGUI»)                |
| `version`      | `u16`    | `1`                                        |
| `pid`          | `u32`    | pid клиента                               |
| `capabilities` | `u32`    | битовая маска возможностей (сейчас `0`)    |
| `app`          | строка   | имя приложения, например `pagh-files`      |

### 3 — `create_window`

| Поле        | Тип    | Значение                          |
|-------------|--------|-----------------------------------|
| `window_id` | `u32`  | идентификатор окна у клиента      |
| `width`     | `u16`  | ширина поверхности в пикселях     |
| `height`    | `u16`  | высота поверхности в пикселях     |
| `format`    | `u8`   | код формата                       |
| `title`     | строка | заголовок окна                    |

Ответ сервера — `configure`; композитор может прислать его с другим размером
(например, если окно не помещается на экран).

### 5 — `commit_frame`

| Поле        | Тип      | Значение                                |
|-------------|----------|-----------------------------------------|
| `window_id` | `u32`    | окно                                    |
| `sequence`  | `u32`    | монотонный номер кадра (начинается с 1) |
| `width`     | `u16`    | ширина кадра                            |
| `height`    | `u16`    | высота кадра                            |
| `stride`    | `u16`    | байт в строке                           |
| `format`    | `u8`     | код формата                             |
| `pixels`    | буфер    | `stride × height` байт                  |

`v1` присылает полную поверхность без damage-прямоугольников: при 1280×800 и
XRGB8888 это 4 МиБ на кадр, что для локального сокета приемлемо. Damage будет
добавлен во `v2` как отдельное сообщение; клиенты обязаны игнорировать
неизвестные типы сообщений с ошибкой, а не молча.

### 7 — `close`

| Поле        | Тип   | Значение |
|-------------|-------|----------|
| `window_id` | `u32` | окно     |

## Сообщения сервера

### 2 — `welcome`

| Поле            | Тип   | Значение                             |
|-----------------|-------|--------------------------------------|
| `magic`         | `u32` | `0x50475549`                         |
| `version`       | `u16` | `1` (несовпадение — ошибка)           |
| `server_pid`    | `u32` | pid композитора                      |
| `screen_width`  | `u16` | ширина экрана                        |
| `screen_height` | `u16` | высота экрана                        |
| `format`        | `u8`  | предпочтительный формат пикселей     |
| `max_frame`     | `u32` | максимальный принимаемый кадр, байт  |

### 4 — `configure`

| Поле        | Тип   | Значение            |
|-------------|-------|---------------------|
| `window_id` | `u32` | окно                |
| `width`     | `u16` | новая ширина        |
| `height`    | `u16` | новая высота        |

### 6 — `input`

| Поле        | Тип   | Значение                    |
|-------------|-------|-----------------------------|
| `window_id` | `u32` | окно-адресат                |
| `event`     | событие | см. ниже                  |

События (`u8` тип + поля):

| Код | Событие           | Поля                                           |
|-----|-------------------|------------------------------------------------|
| 0   | указатель         | `i16 x, i16 y`                                 |
| 1   | кнопка мыши       | `i16 x, i16 y, u8 button, u8 pressed`          |
| 2   | колесо            | `i16 x, i16 y, i16 delta_x, i16 delta_y`       |
| 3   | клавиша           | `u32 code, u8 pressed, u8 modifiers`           |
| 4   | фокус             | `u8 gained`                                    |

`button`: 0 — левая, 1 — средняя, 2 — правая (как `BTN_LEFT/BTN_MIDDLE/BTN_RIGHT`).
`modifiers`: бит 0 — Shift, бит 1 — Ctrl, бит 2 — Alt.

`code` клавиши повторяет Linux `KEY_*` для управляющих клавиш; печатные
символы кодируются как `0x1000_0000 | codepoint`. Готовые соответствия —
`pagh_ui::event::Key::protocol_code()` / `from_protocol()`.

### 8 — `closed`

| Поле        | Тип   | Значение                    |
|-------------|-------|-----------------------------|
| `window_id` | `u32` | окно закрыто композитором   |

### 9 — `error`

| Поле      | Тип    | Значение                     |
|-----------|--------|------------------------------|
| `code`    | `u32`  | код ошибки                   |
| `message` | строка | человекочитаемое описание    |

## Пример обмена

```text
клиент → hello(pid, "pagh-files")
сервер → welcome(screen=1280x800, format=XRGB8888, max_frame=16MiB)
клиент → create_window(1, 1060x640, XRGB8888, "Домашняя папка — Files")
сервер → configure(1, 1060x640)
клиент → commit_frame(1, seq=1, ...)
сервер → input(1, кнопка мыши x=520 y=300 button=0 pressed=1)
...
клиент → close(1)
сервер → closed(1)
```

## Ограничения v1

- Нет `SCM_RIGHTS`/memfd: кадр идёт копией по сокету. `ShmSurface` появится,
  когда ядро и композитор договорятся о разделяемой памяти (kernel PR с
  `mmap(MAP_SHARED)` для memfd).
- Нет damage-прямоугольников, буфера обмена, drag-and-drop, курсора
  (курсор рисует композитор по своему `input`, клиент его не получает).
- Один клиент — много окон; окна не перекрываются протоколом (z-order
  решает композитор).
- Неизвестный тип сообщения — ошибка протокола (`ProtocolError`), соединение
  разрывается; это осознанно строгая политика до появления версионирования
  расширений.
